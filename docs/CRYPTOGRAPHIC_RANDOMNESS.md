## 1. Why Math.random() is Insecure for Passwords

The JavaScript `Math.random()` function is a Pseudo-Random Number Generator (PRNG), typically implemented via algorithms like `xorshift128+` or `V8 xoroshiro128+`.

### Vulnerability:

1. **Predictability:** PRNG algorithms maintain a deterministic internal state of 128 bits.
2. **State Reconstruction:** An attacker who observes just 2 or 3 consecutive outputs can invert the mathematical recurrence relation and reconstruct the PRNG seed in milliseconds.
3. **Outcome:** Every subsequent password or token generated by the application becomes 100% predictable.

**PassGuard Rule:** `Math.random()` is strictly prohibited across the entire codebase.

## 3. The Modulo Bias Problem & Mathematical Solution

### 3.1 What is Modulo Bias?

Suppose we have a 32-bit unsigned random integer $R \in [0, 2^{32} - 1]$ and we wish to pick a random character from a set of size $N = 95$ characters.

The naive approach is:
$$\text{index} = R \bmod 95$$

Because $2^{32} = 4,294,967,296$ is not evenly divisible by $95$:
$$4,294,967,296 = (45,210,182 \times 95) + 6$$

This means:

- The remainder values $0, 1, 2, 3, 4, 5$ will be generated by $45,210,183$ possible outcomes of $R$.
- The remaining values $6$ through $94$ will be generated by only $45,210,182$ possible outcomes.

The characters mapped to indices $0$ through $5$ have a higher probability of being chosen. In security cryptography, this is known as **modulo bias**.

### 3.2 PassGuard's Rejection Sampling Algorithm

To eliminate this bias with 100% mathematical perfection, PassGuard calculates the largest multiple of $N$ that fits within a 32-bit unsigned integer:

$$\text{limit} = 2^{32} - (2^{32} \bmod N)$$

Any random candidate $R \ge \text{limit}$ is rejected and resampled:

```typescript
export function getSecureRandomInt(maxExclusive: number): number {
  if (maxExclusive <= 0) {
    throw new Error("maxExclusive must be greater than 0");
  }
  if (maxExclusive === 1) return 0;

  const MAX_UINT32 = 0x100000000;
  const limit = MAX_UINT32 - (MAX_UINT32 % maxExclusive);
  const buffer = new Uint32Array(1);

  while (true) {
    crypto.getRandomValues(buffer);
    const candidate = buffer[0];
    if (candidate < limit) {
      return candidate % maxExclusive;
    }
  }
}
```

### 3.3 Probability Proof

For any $k \in [0, N - 1]$, the number of values in $[0, \text{limit} - 1]$ that yield $k$ under modulo $N$ is exactly:
$$M = \frac{\text{limit}}{N} = \lfloor \frac{2^{32}}{N} \rfloor$$

Since each candidate $R < \text{limit}$ is drawn with equal probability:
$$P(X = k) = \frac{M}{\text{limit}} = \frac{M}{M \times N} = \frac{1}{N}$$

The distribution is **strictly uniform**, and modulo bias is completely eliminated.
